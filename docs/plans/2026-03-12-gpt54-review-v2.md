- `mark_cancelled()` must set the event BEFORE cleanup
- `_run_research_with_clarification()` must check cancelled state after wakeup and return early

### Fix 2: Strengthen ClarificationStore abstraction
- Add `async def wait_for_resolution(self, job_id, timeout) -> ClarificationState | None` to abstract base
- Use that in `_run_research_with_clarification()` instead of directly using `get_event()`
- Makes Redis swap actually possible

### Fix 3: Stop leaking clarification state
- Delete state when job completes/fails/cancelled
- Otherwise states accumulate forever in memory

### Fix 4: Don't hide clarification prompt before submit succeeds
- Frontend should only clear prompt after API returns accepted
- Handle expired/cancelled explicitly
- Add submitting/disabled state to prevent double-clicks

### Fix 5: Validate clarification answers properly
- Strip whitespace before validation
- Enforce max_length (500 chars suggested)
- Use pydantic field_validator

### Fix 6: Correct token usage labeling
- Research path only tracks synthesizer (not clarifier/planner/researcher/compressor)
- Streaming path gets zero tokens
- Either instrument all nodes or change scope label to "partial_job" / "answer"

### Fix 7: Return more precise /clarify statuses
- Differentiate: accepted, already_answered, expired, cancelled, mismatch
- Currently everything non-pending returns generic "expired"
